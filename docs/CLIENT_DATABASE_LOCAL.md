Telegram из Excel сохранён как контакт; для входа привязка аккаунта выполняется отдельно.

## Правила переноса

- «Сервер»: расширенный доступ; «Техничка»: базовое сопровождение; «Полный»: оба сервиса.
- «Индивидуальный»: базовое сопровождение с индивидуальной ценой из Excel.
- «Самостоятельно»: без платной подписки FOX POINT.
- Модель и серийный номер остаются пустыми, поскольку их нет в исходнике.
- Цена оплаченных стандартных тарифов взята из суммы оплаты / числа месяцев. Для строк без оплаты: сервер/техничка 1000 ₽, полный 2000 ₽. Число 149 в ручной колонке не считается ценой этих тарифов.
- Исторический период пересчитан от даты первой подписки: число месяцев × 30 суток. Календарная формула EDATE из Excel не используется; сроки поэтому могут отличаться на несколько дней.
- Каждая записанная оплата хранит сумму и добавленные дни. Продление добавляет дни к `max(окончание, момент оплаты)`. Повтор одного запроса не продлевает подписку снова.
- Повторный импорт пропускает уже импортированные роутеры и не перезаписывает последующие изменения и оплаты.
- Код физического роутера сохраняется при смене владельца, чтобы существующая табличка/QR продолжала работать. Код текущего клиента показан отдельно.

## Подготовка и импорт

Для подготовки JSON из исходного XLSX нужен Python с openpyxl:

```powershell
python scripts/prepare-client-database.py "C:/Users/k.zolotarev95/Desktop/FOX POINT — База клиентов и роутеров.xlsx"
```

Команда не изменяет Excel и не заменяет уже существующий JSON. Для повторной подготовки укажите новое имя через `--output scripts/data/register-new.json`.

Перед импортом остановите локальный preview. Поднимите только локальную БД в отдельном терминале:

```powershell
node .codex-temp/local-db-runtime/node_modules/@electric-sql/pglite-socket/dist/scripts/server.js --db=.codex-temp/local-postgres --port=55432 --host=127.0.0.1 --max-connections=1
```

Во втором терминале:

```powershell
$env:DATABASE_URL = 'postgresql://postgres:postgres@127.0.0.1:55432/postgres?schema=public&connection_limit=1&pgbouncer=true'
npm run db:import-clients -- --dry-run
npm run db:import-clients
```

После завершения остановите отдельную БД Ctrl+C и запустите preview. Этот локальный адаптер допускает одно подключение: импорт и API запускаются по очереди. Для нового окружения сначала выполните `npm run db:generate`, `npm run db:push` на пустой локальной БД и `npm run build`.

## Резервные копии и откат

В `.codex-temp/backups` сохранены исходный diff рабочей копии, снимки таблиц перед импортом, копия до разделения роутеров Богдана и полная локальная БД после проверки. Перед переносом на VPS дополнительно потребуется штатный `pg_dump` рабочей PostgreSQL и архив текущего кода. Локальные JSON-снимки служат для проверки импорта и не заменяют полный резервный дамп VPS.

Файл `local-client-db-ready.zip` содержит текущий локальный код, исходный Excel и каталог локальной БД. Для восстановления локальных данных остановите preview, распакуйте архив в отдельную папку и скопируйте его `.codex-temp/local-postgres` в рабочую папку после сохранения текущего каталога. Код из архива можно сравнить/восстановить пофайлово. Старые пользовательские изменения сохранены отдельным patch.

Исходники ведутся в ветке `codex/client-router-db-local`. Реестр с контактами, локальная БД и резервные копии исключены из Git; перенос данных на VPS выполняется отдельно от публикации кода.

## Проверка фикса на VPS без GitHub

В Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\FoxPoint\scripts\deploy-local-fix.ps1"
```

По умолчанию используется SSH `root@64.112.127.235`. Если ваш SSH-пользователь другой, добавьте `-SshUser имя`. У него должен быть доступ к sudo. При входе вводится обычный пароль VPS либо используется уже настроенный SSH-ключ.

Скрипт отправляет исходники и подготовленный реестр, собирает отдельную копию проекта, останавливает сервисы на время переноса и сохраняет полный `pg_dump` и прежний каталог `/opt/foxpoint_store`. Затем применяет добавления к схеме, импортирует реестр и запускает сервисы. Настройки `.env` берутся с VPS; GitHub не меняется. Если Prisma требует потенциально опасный переход схемы, обновление прекращается. При ошибке после остановки сервисов скрипт пытается восстановить прежнюю версию.

Каталог резервной копии `/opt/foxpoint-backups/fix-ДАТА-ВРЕМЯ-ID` и точная команда `sudo bash .../rollback.sh` выводятся в терминале. Ручной откат предварительно сохраняет текущее состояние БД и возвращает код и БД к состоянию до фикса. Данные, поступившие после установки фикса, будут в дополнительном дампе, но не в восстановленной старой БД.

Для проверки одной упаковки без подключения к серверу добавьте `-PrepareOnly`. Само выполнение на VPS должно быть проверено по выводу команды и в админке.
