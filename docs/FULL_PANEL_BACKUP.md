# Полный бэкап FOX POINT

Раздел **Админка → Навигация → Бэкап** создаёт один файл `.foxbackup` для восстановления приложения на текущем сервере или переноса на новый. В истории репозитория до этого изменения отдельной функции полного бэкапа в админке не было; резервные копии существовали в терминальных скриптах установки фиксов.

## Что сохраняется

- Вся PostgreSQL-база приложения: все таблицы и схемы, связи, индексы, последовательности, клиенты, роутеры, оплаты, подписки, обращения и сообщения, аккаунты и хеши паролей, сессии, рефералки, баланс, уведомления, аудит и настройки. Используется полный `pg_dump` в custom-формате.
- Весь каталог приложения, включая `.env`, исходники сохранённой версии, публичные файлы, uploads, приватный реестр и `.git`, если он есть. Файлы не отбираются по Git и не ограничиваются известными моделями данных.
- Конфигурация FOX POINT в Nginx, оба systemd-сервиса и сертификаты Let's Encrypt для адреса панели, если они есть.
- Манифест с датой, исходным адресом, версиями Node/PostgreSQL, контрольной суммой дампа и перечнем таблиц. Число записей в манифесте является справочным: при изменении работающей базы сразу после дампа счётчик может отличаться от снимка; сам дамп использует согласованный снимок PostgreSQL.

Исключаются генерируемые каталоги `node_modules`, `.next`, `dist`, `.turbo`, `__pycache__` и локальная техническая папка `.codex-temp`. Зависимости и сборка создаются из сохранённого `package-lock.json` и исходников. Это полная резервная копия приложения FOX POINT, а не образ ОС, чужих сайтов или всего VPS. Файлы приложения должны храниться в его каталоге, как в штатной установке; внешнее хранилище требует отдельной интеграции.

Архив шифруется AES-256-GCM; ключ получается из пароля через scrypt с индивидуальной случайной солью. Требуется пароль от 12 до 256 символов. Пароль не записывается в список бэкапов. На сервере архивы и журнал операций хранятся в `/opt/foxpoint-panel-backups` с закрытыми правами. Загрузки защищены подписанной сессией администратора, в том числе при запросах через localhost. Неверный пароль, повреждённый архив и опасные пути распаковки отклоняются до восстановления.

Максимум: 20 ГБ на зашифрованный архив, 100 ГБ после распаковки, 250 тысяч записей архива. При превышении выдаётся ошибка, частичная копия не выдаётся как готовая. Для создания и восстановления должно хватать диска на временную распаковку, новую базу, сборку и предыдущую панель.

## Создать и сохранить копию

1. Откройте **Бэкап**, задайте пароль архива дважды и нажмите **Создать полный бэкап**.
2. Дождитесь статуса **Готов** и скачайте файл на свой компьютер.
3. Сохраните пароль отдельно. Для нового VPS скачайте также **установщик восстановления** из этой страницы: он содержит собственный код восстановления, поэтому не зависит от будущих изменений GitHub.

Резервные копии не удаляются автоматически. Скачивайте их за пределы VPS: потеря всего сервера уничтожит копии, оставшиеся только на нём.

## Удалить ненужный архив

В разделе **Архивы и ход операций** нажмите **Удалить архив**, затем **Да, удалить с сервера**. Удаляются сам файл `.foxbackup`, его незавершённые части и запись в списке; панель покажет размер удалённых файлов. Скачанная на компьютер копия сохраняется. Удаление выбранного для восстановления архива сбрасывает выбор.

Во время создания, загрузки или восстановления архивов удаление заблокировано на сервере. Незавершённую операцию удалить нельзя. У завершившейся с ошибкой операции кнопка **Удалить запись** убирает запись и оставшиеся части её архива. Показываются все сохранённые архивы, включая старые. История восстановления, его рабочие каталоги и резервные копии установки фиксов этой кнопкой не удаляются.

## Восстановить текущую панель

Загрузите `.foxbackup` и введите его пароль, либо выберите уже готовую копию. Архив сначала полностью проверяется. Затем укажите адрес сайта, пароль и подтверждение **ВОССТАНОВИТЬ**.

Восстановление выполняет отдельный systemd-процесс, который продолжает работу при перезапуске API. Сначала база восстанавливается в отдельную PostgreSQL-базу, затем собирается сохранённая версия приложения. `db push` и повторный импорт Excel не выполняются. Перед заменой создаётся полный архив текущей панели `before-restore.foxbackup` в закрытом рабочем каталоге операции. Для него используется пароль восстанавливаемого архива.

После проверки сборки сервисы останавливаются, сохраняется последняя полная копия текущего состояния и переключаются каталог приложения, Nginx и сервисы. Панель недоступна на время этой копии и переключения. Проверяется запуск API с доступной БД и страницы входа. При ошибке переключения возвращаются предыдущий каталог и конфигурация. Предыдущая база не удаляется и не перезаписывается. Файлы операции сохраняются в `/opt/foxpoint-panel-backups/worker-ID/work`; при запуске из админки автоматическая копия добавляется в общий список архивов как **Автоматическая полная копия перед восстановлением** и её можно скачать. При запуске терминального установщика файл `before-restore.foxbackup` остаётся в рабочем каталоге операции. После восстановления используйте логин и пароль администратора из сохранённой версии. Изменения, поступившие после даты выбранного архива, будут в автоматической копии текущего состояния.

Для восстановления на тот же домен с HTTPS используются сохранённые сертификаты; существующие актуальные сертификаты сервера сохраняются. При переходе на новый IP/домен сначала укажите `http://IP-ИЛИ-ДОМЕН`, затем настройте HTTPS. Для восстановления используется та же основная версия PostgreSQL, что в архиве, чтобы обеспечить совместимость базы. При несовпадении версии восстановление через панель прекращается до замены.

## Новый VPS

Поддерживается штатная установка Ubuntu/Debian с systemd и каталогом `/opt/foxpoint_store`. Нужны доступ root/sudo, интернет для установки пакетов и свободные порты 80, 3000, 4000, 5432. Загрузите архив и скачанный установщик на новый сервер. Из его терминала:

```bash
sudo bash restore-foxpoint.sh /root/ИМЯ-АРХИВА.foxbackup http://IP-НОВОГО-СЕРВЕРА
```

Установщик запросит пароль без отображения, установит Node.js, Python, PostgreSQL и Nginx, восстановит базу, конфигурацию и сохранённые исходники, соберёт и запустит панель. При необходимости на новом сервере установится исходная основная версия PostgreSQL из официального PostgreSQL apt-репозитория. На существующем сервере автоматическое изменение версии/порта PostgreSQL не выполняется.

Не запускайте обычный `update-vps.sh` сразу после восстановления неопубликованного локального фикса: обновление из `main` заменит сохранённые исходники версией GitHub.

## Локальная установка фикса на VPS без пуша

Из Windows PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\FoxPoint\scripts\deploy-local-fix.ps1"
```

Скрипт отправит локальные исходники на `64.112.127.235`, сохранит текущий код и дамп, соберёт новую версию и покажет точную команду отката. Добавление больших загрузок в Nginx сохраняет действующий адрес и TLS-настройки. GitHub не изменяется. `-PrepareOnly` проверяет упаковку без подключения к VPS.

## Проверки

### Исправление цикла переадресации страницы бэкапа

В прежнем Nginx-блоке `location ^~ /admin/backups/` сервер автоматически добавлял слэш к `/admin/backups` (301), а Next.js убирал его обратно (308). Исправление добавляет точное `location = /admin/backups`, которое сразу передаёт страницу приложению. Загрузка больших архивов остаётся в отдельном блоке. Скрипт обновляет и уже установленную конфигурацию, сохраняя домен, TLS и порты; перед изменением сохраняет файл с датой, проверяет `nginx -t` и только затем перезагружает Nginx.

Для применения только этого исправления из Windows PowerShell без пересборки приложения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\k.zolotarev95\Documents\FoxPoint\scripts\fix-backup-redirect.ps1"
```

Скрипт сохраняет действующую конфигурацию и три затронутых файла приложения в `/opt/foxpoint-backups/redirect-ДАТА-ВРЕМЯ-ID`, проверяет конфигурацию и перезагружает только Nginx. Точная команда отката печатается в терминале. Исправленные шаблоны сохраняются и в установленной панели для будущих полных бэкапов и переноса.

После успешного выполнения откройте `https://foxpoint.cc/admin/backups?redirect-fix=1` — новый параметр помогает обойти ранее закэшированный постоянный редирект. `npm run test:backup-nginx` проверяет обновление существующих конфигураций, повторный запуск, сохранение TLS/доменов/портов и шаблоны для нового VPS.

Поведение описано в [документации Nginx location](https://nginx.org/en/docs/http/ngx_http_core_module.html#location) и [Next.js trailingSlash](https://nextjs.org/docs/app/api-reference/config/next-config-js/trailingSlash).

`npm run test:backups` требует отдельную одноразовую PostgreSQL-базу с актуальной схемой. Её имя должно содержать `backup_test`, адрес передаётся в `BACKUP_TEST_DATABASE_URL`. Тест добавляет записи во все 17 моделей, создаёт полный зашифрованный архив, восстанавливает его в отдельную базу и сравнивает каждое поле каждой записи, включая JSON, decimal, даты, парольные хеши, сессии и последовательности. Проверяются файлы/`.env`, повреждение архива, неверный пароль, одновременные операции, авторизация и безопасная распаковка. Тест изменяет только указанную одноразовую исходную БД и временную БД восстановления.

Локальный preview на Windows может создавать, скачивать, загружать и проверять архивы при установленной настоящей PostgreSQL и её утилитах `pg_dump`/`pg_restore`/`psql`. Замена сервисов и системной конфигурации доступна на Linux VPS.

Первичные источники: [pg_dump](https://www.postgresql.org/docs/current/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/current/app-pgrestore.html), [официальный apt-репозиторий PostgreSQL](https://www.postgresql.org/download/linux/ubuntu/).
